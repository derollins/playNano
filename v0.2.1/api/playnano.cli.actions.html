class playnano.cli.actions.Wizard(input_file: str, channel: str, output_folder: str | None, output_name: str | None, scale_bar_nm: int | None, io: IO | None = None)[source]¶

Bases: object

Interactive processing + analysis wizard.

This class provides a REPL interface for building and running processing and analysis pipelines on AFM data. Users can add, remove, reorder, save, and load both processing and analysis steps. Processing steps operate on 2D image data and are applied in sequence to a stack, while analysis steps are executed on the processed data or raw data if no processing is specified.

The wizard can be driven interactively through text commands. It supports saving and loading pipelines from YAML or JSON files, exporting processed stacks in multiple formats, and creating animated GIFs.

Examples

>>> wiz = Wizard("data.afm", "height", ".", "output", 100)
>>> wiz.run()
Parameters:

  • input_file (str) – Path to the AFM input file.

  • channel (str) – Channel name to load from the AFM file (e.g. “height_trace”).

  • output_folder (Optional[str]) – Directory to write exported analysis/processing outputs. If None, the output directory defaults to the current working directory when an export is performed (see _run_analysis_and_export).

  • output_name (Optional[str]) – Base filename (no extension) for exported files. If None, the stem of input_file will be used at export time.

  • scale_bar_nm (Optional[int]) – Default scale bar size in nm used when creating GIFs. Use 0 to explicitly disable the scale bar. This value is passed to export_gif as given; that function determines how to interpret 0.

  • io (IO or None, optional) – I/O abstraction used for reading commands and printing output. If None, standard input/output will be used. Mainly for testing and automation.

handle_arun(parts: List[str]) → None[source]¶

Execute the analysis pipeline, running processing if needed and export results.

The function supports two modes: - If the wizard has processing steps configured (self.process_steps), it will

ensure the processed stack is available and up-to-date and then run analysis in-memory on that processed stack.

  • If there are no processing steps, analysis runs directly on the loaded AFM

stack.

Results are exported as JSON and HDF5 into self.output_folder (or current directory). The JSON is created with make_json_safe and both JSON/HDF5 are written atomically.

Parameters:

parts (List[str]) – Tokenized CLI command (unused).

playnano.cli.actions.analyze_pipeline_mode(input_file: str, channel: str, analysis_str: str | None, analysis_file: str | None, output_folder: str | None, output_name: str | None) → None[source]¶

Run an analysis pipeline on an AFM stack and export both JSON and HDF5.

Steps¶

  1. Load the AFMImageStack from disk using input_file and channel.

  2. Parse analysis modules from analysis_file or analysis_str.

  3. Build and execute an AnalysisPipeline over the stack.

  4. Sanitize the full record (make_json_safe) and write it to <output>.json.

  5. Export the raw record to HDF5 via export_to_hdf5.

param input_file:

Path to the AFM input file.

type input_file:

str

param channel:

Name of the data channel to analyze (e.g., “height_trace”).

type channel:

str

param analysis_str:

Semicolon-delimited inline analysis string, e.g. “feature_detection:threshold=5;particle_tracking”.

type analysis_str:

str or None

param analysis_file:

Path to a YAML/JSON file defining the analysis pipeline.

type analysis_file:

str or None

param output_folder:

Directory in which to write JSON + HDF5 exports.

type output_folder:

str or None

param output_name:

Base filename (no extension) for both <output>.json and <output>.h5; defaults to the stem of input_file.

type output_name:
